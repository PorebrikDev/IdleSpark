## О проекте

Mini Factory — это **idle / incremental game** на Unity: пять заведений (от «Ларька» до «Ресторана») автоматически генерируют валюту, игрок открывает новые машины, улучшает их и активирует буст. Проект демонстрирует чистую архитектуру с разделением логики, конфигурации и UI, JSON-сохранения, интеграцию Unity IAP через события, расширяемую систему аналитики и unit-тесты на игровую логику.

Проект создан как **тестовое задание** и показывает навыки: C#, Unity 6, ScriptableObject-конфиги, событийная архитектура, мобильная сборка под Android, Edit Mode тесты.

## Features

- **5 idle-машин**: от «Ларька» до «Ресторана», каждая со своим CPS, стоимостью открытия и ценой улучшения
- **Автоматический доход**: `CPS × deltaTime` каждый кадр
- **Апгрейды и открытие**: рост уровня, CPS и цены улучшения с прогрессией
- **Временный буст ×2 на 5 минут** с кнопки на карточке машины
- **JSON-сохранение** в `Application.persistentDataPath/save.json`
- **Автосохранение** при уходе в фон и при выходе, ручное — после апгрейда, открытия и покупки
- **Unity IAP**: consumable-продукт `coins_pack_small` (1000 монет), Fake Store для тестов
- **Analytics** через `IAnalyticsProvider` с console-провайдером и поддержкой нескольких провайдеров
- **Unit-тесты** логики машины в Edit Mode
- **Android build**: собран APK и проверен на устройстве

## Запуск проекта в Unity

1. Установить **Unity 6000.3.22f1**

## Игровая экономика и idle-механика

### Машины

- 5 машин (заведений): от «Ларька» до «Ресторана»
- Состояния: `Locked` / `Unlocked`, уровень, производительность (CPS), стоимость открытия, стоимость следующего улучшения
- Первая машина открыта сразу, остальные — за игровую валюту
- Названия меняются по уровням через `NameStages` в конфиге

### Экономика

- Монеты капают автоматически: `CPS × deltaTime` каждый кадр
- Общая производительность — сумма CPS всех открытых машин
- Апгрейд увеличивает уровень и CPS
- Цена апгрейда растёт с уровнем

### Boost

- Кнопка на карточке машины активирует временный буст (×2 к CPS на 5 минут)
- Работает только в онлайне, не сохраняется между запусками

## Сохранение прогресса

- JSON-файл в `Application.persistentDataPath/save.json`
- Сохраняются: монеты, состояние машин (уровень, открыта), время выхода
- Автосохранение при уходе в фон и при выходе
- Ручное сохранение после апгрейда, открытия, покупки

## Unity IAP и покупки

- Consumable-продукт `coins_pack_small` (1000 монет)
- Fake Store для тестирования
- Обработано: инициализация, получение продукта, успешная покупка, неуспешная покупка (`UserCancelled`), недоступность магазина
- Игровая логика не зависит от Unity IAP — работает через события

## Analytics и события

- Система событий через `IAnalyticsProvider`
- Console / Debug провайдер
- Архитектура поддерживает несколько провайдеров одновременно
- События: `game_started`, `machine_upgraded`, `machine_unlocked`, `boost_started`, `purchase_succeeded`, `purchase_failed`

## Архитектура проекта

Разделение на три слоя.

### Логика (без Unity UI)

- `Mashine` — данные одной машины: уровень, состояние, CPS
- `Controller` — логика фабрики: тик монет, апгрейды, открытие, буст

### Конфигурация

- `DataMashine` (ScriptableObject) — базовые параметры машины: `BaseCps`, `UnlockCost`, `NameStages`

### UI

- `MachineCard` — карточка одной машины (префаб)
- `FactoryUI` — создаёт карточки при старте
- `UI` — верхняя панель (баланс, CPS)

### Сохранение

- `SaveData` — формат сейва
- `SaveService` — сохранение и загрузка JSON

### IAP

- `IapService` — обёртка над Unity IAP, работает через события

### Analytics

- `Analytics` — статический фасад
- `IAnalyticsProvider` / `DebugAnalyticsProvider` — провайдеры

## Unit-тесты

- Unit-тесты на логику машины в **Edit Mode**
- Покрыто: апгрейд, рост CPS, проверка нехватки монет

## Известные ограничения

- Офлайн-прогресс не реализован. Сохраняется `LastExitTime`, но при возврате доход за отсутствие не начисляется.
- Буст не сохраняется — работает только в онлайне и сбрасывается при перезапуске.
- Параметры буста (5 минут, ×2) заданы в коде, а не в конфиге.
- Analytics — только console-провайдер. Реальные SDK (Firebase, AppMetrica) не подключены.
- UI на мобильных экранах требует доработки: Canvas Scaler и Safe Area для устройств с вырезом и скруглениями.
- Художественная часть — плейсхолдеры: простые спрайты и стандартный UI.

## Roadmap
